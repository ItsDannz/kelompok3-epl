## Baseline yang harus direkam oleh masing-masing pemilik sebelum mengubah modul

1. Buat fixture deterministik kecil terpisah dari demo acak: waktu dibekukan, timezone tetap, tax0 kecuali skenario pajak, product price10000/cost6000 dan pivot stock10; warehouseA/B pada outlet berbeda; role super-admin/manager/cashier serta token abilities eksplisit. Fixture piutang/hutang total100000 paid0, due date masa depan dan satu due date lampau.
2. Jalankan karakterisasi terhadap source baseline, simpan input, output HTTP/Inertia, pesan/error keys, redirect, snapshot DB sebelum/sesudah, audit events dan bukti UI. **Test karakterisasi tambahan ini belum dijalankan.**
3. Untuk pasangan web/API, bandingkan masing-masing endpoint dengan baseline-nya; JSON tidak harus sama dengan redirect Inertia. Simpan nullable/missing field, tipe int/float/string dan ordering.
4. Setelah refactoring, reset ke fixture dan kondisi yang sama, jalankan ulang skenario persis; bandingkan output dan side effect. Normalisasi hanya UUID/ID/timestamp acak yang disepakati, jangan menyembunyikan perubahan total/status/stok/akses.
5. Pisahkan test yang mengunci perilaku lama dari test bug fix yang mengharapkan perilaku baru. Bila characterization menemukan kegagalan lama, catat BF terpisah dan jangan membuatnya hilang diam-diam dalam commit RF.

## Perintah berdasarkan tooling aktual

Perintah berikut berlaku setelah setup PHP8.3/8.4 serta dependensi yang sesuai. Test baseline nyata dijalankan dengan PHP8.4.15; package PhpSpreadsheet di lockfile menolak PHP8.5. Jangan memakai --ignore-platform-reqs untuk menyamarkan ketidakcocokan.

```bash
php -d memory_limit=1G vendor/bin/phpunit --log-junit ../hasil-baseline.xml
php artisan test --filter='ProductStoreTest|ProductUnitTest|CompositeProductTest|ProductTaxTest'
php artisan test --filter='MemberManagementTest|CrmCoreTest'
php artisan test --filter='PaymentIntegrityTest|V1FinanceApiTest|SalesReturnTest'
php artisan test --filter='CheckoutServiceTest|CheckoutStockIntegrityTest|BatchAllocationTest|DineOrderTest'
php artisan test --filter='AdvancedSalesInsightsTest|V1DashboardApiTest|HandleInertiaRequestsTest'
PUPPETEER_SKIP_DOWNLOAD=true npm run build
# Pemeriksaan gaya saat implementasi, bukan dilakukan sekarang karena Pint dapat mengubah source:
vendor/bin/pint --test
```

`php -d memory_limit=1G vendor/bin/phpunit` memperbesar proses PHPUnit langsung. Untuk `php artisan test` yang memulai subprocess, konfigurasi memory_limit lewat php.ini/PHPRC juga harus diwariskan (seperti run audit). Tidak ada script frontend lint/typecheck/test di package.json. `node --test tests/frontend/money.test.mjs` hanya USULAN setelah file test utility benar-benar dibuat; **belum dijalankan**, bukan perintah yang saat ini sudah tersedia sebagai suite repo. Tidak mengklaim PHPUnit melindungi browser React/IndexedDB.

Kriteria sukses paket inti: semua skenario karakterisasi yang relevan hijau pada baseline dan hasil refactor dengan input sama; 580 test baseline tetap lulus,1 skip dilaporkan atau diganti bukti imagick; tidak ada perubahan API/error keys/permissions/DB/audit; UI create/edit/customer/payment/checkout tetap; build lolos; tiap RF punya commit dan before/after. Bug lama ditandai, bukan disembunyikan oleh snapshot normalization. Belum ada hasil sesudah refactoring pada audit ini.
